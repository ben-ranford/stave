# ADR-014: Lopper adopts through an application-owned strangler adapter

- Status: Accepted
- Date: 2026-08-12
- Owner: Lopper owner
- Proof command: Lopper worktree parity suite (release blocker until merged)

## Context

Lopper already has its own domain model, command grammar, confirmation policy, and side-effect seams. Replacing it wholesale would create unnecessary migration risk.

## Decision

Adopt Stave in Lopper through an application-owned strangler adapter that preserves Lopper behavior while incrementally moving semantic rendering and machine control onto Stave.

## Consequences

- Migration stays reversible.
- Lopper semantics remain outside the reusable core.
- Shadow and parity testing are mandatory before default-on rollout.
