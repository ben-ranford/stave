# ADR-006: One owner serializes reductions; effect outcomes are recorded events

- Status: Accepted
- Date: 2026-08-12
- Owner: Runtime owner
- Proof command: `go test ./session ./runtime/...`

## Context

Concurrent effects may finish in different orders, but deterministic state evolution still requires one authoritative reduction order.

## Decision

One session owner serializes reductions. Effect outcomes become explicit recorded events instead of mutating state directly.

## Consequences

- Deterministic transcripts remain possible.
- Queue and backpressure policy can be applied in one place.
- Out-of-session or post-close effect outcomes can be discarded safely.
